The OSI Model & TCP/IP in Live SOC Defense

As a SOC Analyst, you don't just "know" the OSI model; you live in it. Every alert in Wazuh, Splunk, or any enterprise SIEM is tied directly to these protocol layers.

1. The Core Focus (The "Security Triad": Layers 2, 3, and 4)

While theoretical networking outlines 7 layers, 90% of telemetry and intrusion alerts originate within layers 2 through 4:

Layer Name Data Unit Security Relevance & Detection Value
Layer 4 Transport Segments Ports (TCP/UDP). Is someone probing port 445 (SMB), 3389 (RDP), or 22 (SSH)?
Layer 3 Network Packets IP Addresses. Is inbound traffic routing from a known malicious C2 or TOR exit node?
Layer 2 Data Link Frames MAC Addresses. Is an attacker performing ARP spoofing or MITM attacks on the LAN?

2. Application in the Wazuh SOC Lab

In our Wazuh active response lab, when a Hydra brute-force alert was generated, the telemetry ingested by the manager parsed:

  • src_ip: 192.168.1.50 (Layer 3 – Network Packet)
  • dst_port: 445 (Layer 4 – Transport Segment)
  • protocol: TCP (Layer 4 – Connection-Oriented)
The Analyst's Mental Model:
"I observe Layer 3 packets from host 192.168.1.50 initiating SYN sequences against Layer 4 destination port 445 via TCP. Correlating with rapid authentication failures confirms an automated SMB dictionary attack."

3. OSI (Theory) vs. TCP/IP (Operational Reality)

OSI (Theoretical) TCP/IP (Real-World) Protocols in Action
Layers 5, 6, 7 Application HTTP/S, DNS, SMTP, SSH, TLS
Layer 4 Transport TCP (Three-Way Handshake), UDP
Layer 3 Internet IPv4, IPv6, ICMP, ARP
Layers 1, 2 Network Access Ethernet (802.3), Wi-Fi (802.11)

?? Practical Defense Takeaway

When tuning firewall rules or Sysmon filters, understanding Layer 4 boundary controls prevents agent disconnects. For example, Wazuh agents report to the manager via TCP port 1514 (data telemetry) and 1515 (enrollment). Blocking Layer 4 halts all Layer 7 dashboard communications.
